# Agent Harness MVP

Цель MVP — организовать выполнение frontend-задач агентом по спецификации с явным результатом каждого запуска.

## Компоненты

- **TypeScript Harness** — управляет запуском агента, контекстом задачи и итоговым статусом.
- **LLM CLI** — запускает агента для выполнения задачи и изменения кода.
- **OpenSpec** — хранит требования и критерии приёмки задачи.
- **Codebase MCP** — предоставляет агенту доступ к структуре и контексту кодовой базы.
- **UI MCP** — позволяет проверять интерфейс и взаимодействовать с ним.
- **Frontend agent** — реализует изменения интерфейса и проверяет их по критериям приёмки.

## Сценарий работы

Harness получает задачу и спецификацию OpenSpec, передаёт контекст frontend agent через LLM CLI, подключает Codebase MCP и UI MCP и собирает отчёт о выполнении.

## Итоговые статусы

- **COMPLETED** — задача выполнена, критерии приёмки проверены; отчёт содержит изменения и результаты проверок.
- **NEEDS_CLARIFICATION** — для продолжения нужны ответы пользователя; отчёт содержит конкретные вопросы.
- **BLOCKED** — выполнение остановлено препятствием; отчёт содержит причину и необходимое действие для продолжения.

## Реализованный каркас

В MVP добавлены аналитик, отдельные планировщики и исполнители frontend/backend,
а также тестировщик и независимый верификатор. Harness последовательно запускает роли, передаёт артефакты,
сохраняет вопросы для аналитика и повторяет цикл после получения ответов.
Аналитик создаёт proposal и delta specs OpenSpec. Backend-планировщик, затем
frontend-планировщик формируют общие design/tasks; исполнители и тестировщик
отмечают только собственные задачи. Harness проверяет документы и сохраняет версии.
Верификатор проверяет план по specs, затем код по одобренному плану. Отрицательный
review возвращает работу планировщикам или исполнителям. На каждый тип доработки
даются две попытки; затем BLOCKED и эскалация разработчику. PR создаётся кодом
только после одобрения и успешных обязательных проверок.
Обязательные проверки, Git и доставка PR управляются кодом; MCP подключаются
в LLM CLI. Для Codebase MCP и UI MCP подготовлены локальные заглушки.

Инструкция запуска и переноса на рабочий ПК: [README.md](README.md).

После публикации PR запуск получает WAITING_REVIEW. Команда watch отслеживает
треды: review-triager маршрутизирует замечания на исправление плана/кода или ответ.
Исправления проверяются и отправляются в прежнюю ветку; на тред — две коррекции.
COMPLETED для опубликованной задачи наступает после merge, CANCELLED — после
закрытия без merge. Интеграция Bitbucket get/reply пока представлена файловой заглушкой.
