# История выполнения

```sh
agent-harness events <run-id-or-directory>
```

Команда выводит JSON-массив завершённых записей из `.harness/runs/<id>/events.jsonl`.
У старых запусков без этого файла возвращается пустой массив. `status` по-прежнему
читает текущее состояние из state.json. Для events не нужны LLM CLI или доступ к API.

Каждая запись имеет version=1, уникальный UUID, UTC timestamp, runId, iteration,
type и data. Порядок строк — порядок записи, часы не используются для сортировки.

| Событие | Содержимое |
| --- | --- |
| run.started / run.status | Начало задачи, итог этапа, следующий участник |
| run.continued | Продолжение сохранённой задачи и этап её checkpoint |
| workflow.started / workflow.rework | Причина прохода и расход бюджета доработок |
| agent.started / agent.finished / agent.failed | Роль, фаза, путь запроса, результат или ошибка |
| checks.finished / verification.decided | Проверки и структурированное решение верификатора |
| delivery.published | Коммит и PR, если включена публикация |
| review.triaged | Обсуждение и выбранный маршрут |
| review.reply.sent / failed / superseded | Результат отправки сохранённого ответа |

Журнал дописывается при continue, resume и обработке PR. Неизменившийся PR не создаёт
событий запуска модели. Полные запросы, ответы, stdout/stderr и артефакты остаются
в прежних файлах; они не дублируются в журнале. Ошибка процесса и невалидный JSON
записываются как agent.failed. Для верификатора и triager неизменность продуктовых
файлов проверяется также при ошибке агента.

State.json остаётся единственной контрольной точкой. Из журнала нельзя запускать
команды или автоматически восстанавливать выполнение: он нужен для наблюдения.
Полные строки считаются завершёнными записями. Чтение игнорирует незавершённый
последний фрагмент; следующая запись удаляет только этот фрагмент под run.lock.
Повреждённая завершённая строка вызывает ошибку чтения и требует диагностики.

Отказ записи истории добавляется в integrationErrors и не повторяет уже успешный
push/комментарий, не меняет решение верификатора. Это диагностический журнал без
гарантии транзакции между диском, Git и внешним API.
