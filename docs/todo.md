# Запланированные доработки

## Тестовые данные и тест-стори

- [ ] Добавить подготовку тестовых данных для тест-кейсов задачи: воспроизводимые
  скрипты создания данных, параметры окружения, команды запуска и очистки.
  Привязать каждый скрипт к TC-id и описать предусловия. Не включать credentials
  или реальные персональные данные в артефакты.
- [ ] После аппрува PR автоматически вызывать скрипт, создающий тест-стори
  по исходной задаче. В тест-стори включать все актуальные тест-кейсы, связанные
  AC-id, предусловия, шаги, ожидаемые результаты и скрипты подготовки тестовых
  данных с командами и параметрами для самостоятельного воспроизведения.
- [ ] Определить правило аппрува по процессу команды и получать его из Bitbucket.
  Триггер — аппрув PR, а не merge и не внутренний APPROVED верификатора Harness.
  Сейчас pull-request.get возвращает состояние PR, SHA и обсуждения; данных об
  аппрувах в контракте нет. Расширить адаптер, состояние запуска и обработчик.
- [ ] Задать контракт нового скрипта создания тест-стори: место создания и тип
  сущности (например, в трекере задач), связь с исходной задачей и PR, входные
  артефакты, ответ с id/url, авторизацию и обработку ошибок.
- [ ] Сохранять тест-кейсы и скрипты как доступные интеграции артефакты; при
  исправлениях PR использовать актуальную проверенную версию, привязанную к SHA.
  Защитить создание от дубликатов при повторном опросе/потере ответа и определить
  обновление тест-стори при новых изменениях и повторном аппруве.
